# Описание формата файлов-справочников

Справочники читаются из подкаталога `./datasource/` рядом с исполняемым файлом (пути захардкожены — переименовать
или перенести файлы нельзя):

1. [route.txt](#routetxt) — таблица перевода из номера маршрута, используемого в расписании (`schedule.txt`), в
   номера маршрутов "Яндекс.Карты" и "2ГИС";
2. [transport.txt](#transporttxt) — таблица перевода идентификатора транспортного средства в системе-источнике
   координат (Wialon/ЕГТС/gRPC) в идентификатор транспортного средства, используемый в расписании (`schedule.txt`);
3. [schedule.txt](#scheduletxt) — расписание движения транспортных средств.

**Примечание:** все файлы в кодировке **UTF-8**, разделитель — **; (точка с запятой)**.

**Внимание:** заголовки столбцов **писать в файл не нужно** — парсер читает каждую строку файла как запись данных,
без пропуска первой строки. Если в файл попадёт строка-заголовок (например, `number;yandex;2gis`), она будет
воспринята как обычная (ошибочная) запись справочника. Ниже заголовки приведены только для наглядности в документации.

## route.txt

Пример файла (без строки заголовка в реальном файле):

```
102;102;102
102Э;102;102
1;1;1Б
100;100;100
101;101;101
```

Где:

|Столбец|Описание|
|---|---|
|`number`|Номер маршрута в расписании (`schedule.txt`)|
|`yandex`|Номер маршрута, отправляемый в "Яндекс.Карты"|
|`2gis`|Номер маршрута, отправляемый в "2ГИС" *(новая колонка по сравнению с Gps2Yandex)*|

**Примечание:** если номер маршрута в расписании соответствует номеру, который нужно отправлять в карты, запись об
этом всё равно должна присутствовать (перевод "1 в 1" тоже нужно явно прописать).

**Примечание:** если сервис отправляет данные только в одну из карт (например, `TWOGIS_ENABLED=false`), колонку
`2gis` всё равно нужно заполнить — она просто не будет использована.

## transport.txt

Пример файла:

```
353173067906170;E111OK;bus
353173068562600;E222OK;bus
353173068562683;M002CA;bus
```

Где:

|Столбец|Описание|
|---|---|
|`uid`|Идентификатор транспортного средства в системе-источнике координат: `uid` объекта в "Wialon" (Wialon IPS), идентификатор клиента (`Client ID`) в пакете ЕГТС, или `uid`, переданный напрямую через gRPC `StreamGPSData` — во всех трёх случаях сопоставление идёт по этому же полю|
|`state_number`|Уникальный идентификатор транспортного средства в расписании (`schedule.txt`)|
|`type`|Тип транспортного средства, см. допустимые значения ниже|

Допустимые значения для столбца `type`:
* **bus** — автобус;
* **trolleybus** — троллейбус;
* **tramway** — трамвай;
* **minibus** — маршрутное такси.

## schedule.txt

Пример файла:

```
102;E111OK;02/06/2020T06:30:00Z+03:00;02/06/2020T13:30:00Z+03:00
102Э;E222OK;02/06/2020T05:25:00Z+03:00;02/06/2020T12:30:00Z+03:00
1;M002CA;02/06/2020T12:55:00Z+03:00;02/06/2020T14:45:00Z+03:00
```

Где:

|Столбец|Описание|
|---|---|
|`number`|Номер маршрута (соответствует `number` из `route.txt`)|
|`state_number`|Уникальный идентификатор транспортного средства (соответствует `state_number` из `transport.txt`)|
|`begin_period`|Дата и время начала работы транспортного средства на маршруте|
|`end_period`|Дата и время окончания работы транспортного средства на маршруте|

Файл `schedule.txt` формируется внешней учётной системой предприятия (на основании путевых листов) и должен
содержать расписание на текущий момент времени, а также, как правило, на несколько часов вперёд.

## Как эти файлы связаны между собой

Когда приходит координата с `uid`:

1. по `uid` в `transport.txt` находится `state_number` и `type` транспортного средства;
2. по `state_number` и времени сигнала в `schedule.txt` находится текущая активная запись расписания (и её `number`
   маршрута);
3. по `number` в `route.txt` находятся номера маршрута для "Яндекс.Карт" и "2ГИС".

Если хотя бы одно звено не находится (нет `uid` в `transport.txt`, нет активного расписания на этот момент времени
для `state_number`, либо нет `number` в `route.txt`) — координата отбрасывается и в карты/gRPC-подписчикам не
попадает, событие логируется с уровнем `warn`.

При изменении любого из трёх файлов сервис перечитывает его на лету (без перезапуска).
